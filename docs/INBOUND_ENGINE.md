# AAI Inbound Engine

AAI's commercial motion is designed to invert cold outbound: the public developer surface creates an observable assurance problem, and production customers contact AAI when they need deeper controls.

## Funnel

1. Free Assurance Scan
2. Shareable Assurance Snapshot
3. Public Benchmark / Protocol / Failure Observatory
4. GitHub developer integration
5. Production Assurance request
6. Paid assessment
7. Production deployment
8. Continuous assurance + expansion

## Entry surfaces

- `/assure.html` — free representative assessment
- `/playground.html` — benchmark
- `/observatory.html` — failure intelligence
- `/protocol.html` — machine-readable protocol
- GitHub Action — CI/CD assurance verification

## Conversion rule

Do not promise certification from the free scan. The scan creates a technical signal and a reason to request a production assessment. Paid work is scoped around the customer's actual AI estate, controls, integrations, evidence requirements and runtime needs.

## Revenue ladder

- Free: scan, benchmark, protocol, CLI/action
- Paid assessment: fixed scope around one production workflow
- Production assurance: control plane, runtime enforcement, evidence and continuous re-assurance
- Enterprise expansion: additional systems, environments, integrations, policies and private deployment

## Metrics

Track scan starts, completed scans, report shares, production-assurance requests, qualified opportunities, paid assessments, deployments, expansion ARR and time from scan to commercial conversation.
